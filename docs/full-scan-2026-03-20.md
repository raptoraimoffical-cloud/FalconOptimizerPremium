## High-risk optimization families (BSOD / boot instability candidates)
1. **MSI / interrupt-path changes** (USB/GPU/NVMe/controller scope).
2. **BCD timer and platform clock edits** (`disabledynamictick`, HPET/platform-clock style toggles).
3. **Storage controller and NVMe power-state policy edits** (APST/host power/deep sleep/latency policies).
4. **PCIe ASPM and low-level GPU power-state edits** (ULPS and similar).

These are high-risk because they modify interrupt/timing/boot-time behavior and can expose unstable firmware+driver combinations.

## Cursor invisibility likely cause
Most likely root-cause candidate is the tweak:
- `falcon_new_disable_cursor_suppression`

Reason:
- It directly overwrote `HKCU\Control Panel\Desktop\UserPreferencesMask` with a fixed binary payload.
- `UserPreferencesMask` is a packed desktop/shell behavior bitfield, so hard writes can create side effects (cursor rendering/input/UI anomalies).
